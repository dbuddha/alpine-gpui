# Change Fragment Instructions

Read `README.md` in this directory and `docs/engineering/changelog.md`.

- Add one fragment per independently understandable user-facing change.
- Use an allowed filename kind and a unique issue, PR, or date slug.
- Write one complete sentence for application developers.
- Describe observable behavior, compatibility, performance, or security impact.
- Do not include implementation narration, headings, bullets, authors, or AI
  attribution.
- Do not edit another branch's fragment to avoid a filename conflict; choose a
  new unique slug.
- Release PRs consume fragments only after copying their meaning into the root
  changelog.
