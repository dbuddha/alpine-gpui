# Documentation work

- Document implemented behavior and real limitations. Do not promise planned features.
- Read only the affected topic and its source; do not load the whole collection.
- Verify commands, examples and local references that the change affects.
- Update guidance immediately when changed behavior makes it incorrect.
- Batch new explanations after a feature settles or before release; no per-PR ritual.
- Keep prose concise. Do not add a skill, ledger or research package for routine edits.
- Research notes record conclusions, source revisions, evidence and limitations.
- Preserve referenced technical contracts and measurement artifacts when reorganizing.
- Old GitHub issues and immutable historical links supply history, not operating rules.
