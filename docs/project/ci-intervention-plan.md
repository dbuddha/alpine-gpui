# CI intervention and delivery convergence

## Objective and authority

Make required feedback fast, complete, explainable, and reproducible without
weakening Alpine Studio or Alpine GPUI acceptance. Preserve the macOS daily-driver
objective, independent scoped renderer superiority, the M1-M5 acceptance path,
and the bounded P0-P2 remediation cohort. CI recovery is enabling work, not a
replacement product milestone.

This is the repository projection of the owner-approved CI intervention. Live
work, blockers, and accepted evidence belong in GitHub, beginning with
[Defect #510](https://github.com/dbuddha/alpine-gpui/issues/510) and
[native assurance Defect #590](https://github.com/dbuddha/alpine-gpui/issues/590).
The [recorded approval and scope](https://github.com/dbuddha/alpine-gpui/issues/510#issuecomment-5627081728)
cover ordinary implementation, tests, pushes, PRs, and compliant green merges.
Public releases, destructive actions, security changes, and unrelated expansion
are not authorized by this plan. Repository policy and host restrictions remain
binding.

The [daily-driver path](daily-driver-path.md), [milestone gates](milestone-gates.md),
and [claim readiness](claim-readiness.md) retain their acceptance authority.
The evidence registry owns claims. This page owns the stable execution contract;
mdBook navigation and the Wiki must not become alternate live task databases.

## Selection and execution contract

Use Cargo and existing Alpine assurance infrastructure. Do not introduce Nx,
Bazel, a workflow generator, or a second general orchestration platform.
Affected selection must include reverse dependencies, but Cargo dependencies
alone cannot express shader, fixture, script, generated-input, or policy edges.

A gate plan is not an execution receipt. The first selector explains its base,
head, merge base, paths, risk labels, fallback paths, and gate rules; it explicitly
does not claim test discovery or acceptance. Fixture-injected paths must remain
distinguishable from Git-discovered paths. Required zero-selection and failed
discovery are failures, not successful empty work.

Execution receipts must eventually bind source, tested base, workflow/policy,
toolchain, target, features, selectors, discovered/executed/ignored/terminal
counts, durations, and artifact digests through existing assurance contracts.
Preserve distinct passed, failed, blocked, inconclusive, and not-required states.
Do not conflate nested child summaries with the outer test result.

Concurrent admission and completed-work reuse are different problems. An
eligible reuse identity includes source, tested base, policy/workflow revision,
toolchain/target, selected gates, and assurance-affecting metadata. Fresh metadata
validation is mandatory even when execution evidence is reusable. Privileged
metadata handling must not execute untrusted PR code or trust untrusted caches.

## Runtime targets and measurements

### Emergency native execution boundary

The initial CI-I03 correction targets the admitted native workload, not installer
time. The reviewed main run 34575548077 executed 32 native mutation jobs totaling
19,383 job-seconds and 33 Miri jobs totaling 12,460 job-seconds. These are summed
job durations, not CPU time or billing. The observed macOS concurrency was five;
that workload cannot support a universal 15-minute promise.

Ordinary edits confined to the explicitly reviewed non-native Studio leaf
modules may use affected native selection. Native entry points, the monolithic
Studio entry file, native validation, tests, dependencies, build inputs, unsafe
review labels, mixed changes and unknown inputs retain full PR selection.
Consequential ordinary native tests remain selected independently of mutation
emptiness. This first boundary is not a complete Cargo affected graph or a
module-level proof of every consumer.

The first boundary skips the existing 32 native mutation workers only when
every changed source belongs to that reviewed leaf set. The aggregate
independently recomputes the decision from Git and retains a source/base-bound
policy witness. Missing, invalid or contradictory outputs fail closed. The
witness is not an inventory discovery receipt. Full-mode commands, partition
methods, inventories, baselines, terminal receipts and timeouts are unchanged.
A proposed serial discovery job and dynamic matrix were rejected as unnecessary
for this boundary: all its eligible paths are outside the native mutation
source set, so every supported affected selection is already empty.

This changes when exhaustive native assurance is required, not the contents of
the accepted exhaustive inventories. Existing scheduled native obligations stay
required and unchanged. Their unfinished qualification remains unfinished.
Miri affected-package selection is separate pending work. Neither a smaller
policy decision nor a green infrastructure PR establishes the runtime outcome:
acceptance needs measured hosted small-product and native/control-plane cases.

The scoped [CI-I03 decision](https://github.com/dbuddha/alpine-gpui/issues/510#issuecomment-5633212972)
retains the cost baseline, affected/full boundary and acceptance exclusions.

The desired experience is seconds or minutes for small, safely affected changes
and a roughly 15-minute feedback target where measured workloads and capacity
support it. It is not yet a universal maximum or permission to cancel unfinished
assurance. Per-job time, queue delay, critical-path feedback, and summed runner
time are separate quantities.

Calibrate on unchanged workloads and runner classes before setting blocking
budgets. Record source/base, selected inventory, cache state, toolchain, runner,
provisioning, baseline, rebuild, test, cleanup, artifact handling, queue/admission,
first actionable failure, complete feedback, and aggregate runner cost. Measure
cold and warm operation separately, with repeated matched runs rather than a
single favorable sample. Retain incomplete and unfavorable observations.

Recommend best-case, typical, and adverse bounds only after the corresponding
execution is implemented and measured. If formal checks, native isolation,
cold builds, or capacity prevent the target, state the measured constraint.
Do not transfer required assurance to Nightly merely to improve a PR headline.

## Zed reference and adaptation boundary

The workflow research reference is Zed commit
`a57ba9b17c433ea1ebfdec8f649f4fa5a402d03b`, separate from the accepted renderer
comparator pin. Its [test workflow generator](https://github.com/zed-industries/zed/blob/a57ba9b17c433ea1ebfdec8f649f4fa5a402d03b/tooling/xtask/src/tasks/workflows/run_tests.rs)
provides source examples of Cargo metadata, reverse-dependent selection, asset
inputs, script checks, and workflow regeneration. Its
[workflow checks](https://github.com/zed-industries/zed/blob/a57ba9b17c433ea1ebfdec8f649f4fa5a402d03b/tooling/xtask/src/tasks/workflow_checks.rs)
do not by themselves establish complete affected-selection semantics.

Independently implement useful mechanisms and test Alpine's own dependency and
evidence contracts. Do not copy Zed's entire scheduler, assume comparable runner
capacity, or assert that all Zed CI completes within 15 minutes. Workflow timeout
configuration is not a measured runtime guarantee. Upstream influence and any
accepted implementation change belong in Alpine's existing lineage records.

## CI checker skill

`alpine-ci-job-checker` is an approved implementation target, not a claim that the
skill is already installed or effective. It must govern affected-selection
completeness, baseline correspondence, cache identities, useful shard sizing,
duplicate admission, early failure, complete terminal outcomes, and honest
duration reporting. It does not override product scope, authorization, or CI.

Use the repository skill manifest and installation path. Behavioral scenarios
must include omitted consequential inputs, mismatched native baselines, zero
selection, false success from cancellation, inappropriate cache reuse, and
claimed speedups from incomparable workloads. Apply the existing independent
baseline/candidate evaluation and guarded evolution protocol; phrase checks are
only structural validation.

## Completion and reporting

Each checkpoint names the outcome advanced, exact source and tested base,
accepted evidence, active/parked work, remaining blocker, observed feedback cost,
and next falsifiable action. A locally passing script is not hosted acceptance;
selected main CI is not exhaustive Nightly assurance; hosted CI is not physical
macOS latency, VoiceOver, energy, or residency qualification.

The intervention completes only after accepted and published implementation,
completing equivalent assurance, skill integration/evaluation, and defensible
runtime recommendations. Preserve exact-head aggregate and integrated-main
requirements. The wider product goal remains open until its existing M1-M5,
P0-P2, daily-driver, and scoped comparative contracts pass independently.
