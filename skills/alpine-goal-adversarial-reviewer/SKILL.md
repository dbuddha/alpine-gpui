# Alpine goal adversarial reviewer

Use this as the review role, not as an implementation authority. Load the current
bounded goal, repository instructions, exact candidate diff and raw results. The
CI checker owns execution contracts; this skill challenges whether the chosen
work can actually satisfy the objective. Instructions do not establish expertise
or effectiveness by themselves.

## Review admission

Record start, immutable deadline, closeout reserve, consumer, hypothesis,
falsifier, accepted scope and expected artifact. Queues and review consume the
same budget. A context reset is not a new window. If the host cannot enforce an
automatic cutoff, use bounded foreground work rather than an indefinite loop.

Give an independent reviewer the objective, diff, identities and raw results,
without the implementer's preferred conclusion. Do not relay suspected answers
in an evaluation prompt. Report independence limitations when no isolated
reviewer is available. Never start another task or automation for continuity.

## PR challenge checklist

- Does each change remove a demonstrated blocker or test a registered hypothesis?
- Does the cited source support the mechanism, rather than merely name a respected project?
- Is the regression exercised through the affected production boundary?
- Does a negative control fail for the intended reason before expensive work?
- Do packages, features, cfg, environment, selectors and source/base identities correspond?
- Are discovery, execution, terminal outcomes and accepted evidence distinct?
- Does success require nonempty required suites and complete selected inventories?
- Are caches compatible inputs, never recycled success claims or unauthorized trust expansion?
- Are failure observation and actual workflow state separate when transport fails?
- Is the measured benefit relevant, with cache state and timing endpoints fixed in advance?
- Are native failures still open rather than classified away by a faster scheduler?
- Can the candidate finish exact-head and integrated-main checks before closeout?

Never approve gate weakening, omitted mutants, smaller proof bounds, arbitrary
timeout cuts, unchanged reruns for green, wrong executable identity, silent held
work overwrite, unchecked merging, or unrelated infrastructure expansion.

## Disposition

Findings first, ordered by severity, with file/line or raw artifact references,
impact and the smallest discriminating correction. Separate confirmed defects,
hypotheses and evidence gaps. State accepted, incomplete, inconclusive or rejected
for the precise outcome, not the overall project by implication.

A merged mechanism is not editor improvement. Admission safety is not a measured
feedback speedup. Three trials do not justify tail percentiles or worst-case
runtime promises. Favorable scoped evidence is not universal superiority.

At closeout list candidate, merge/main evidence, measurements, unresolved work,
parked changes and the next decision. Stop at the deadline with incomplete work
explicit. After two attempted CI windows, require a product investment checkpoint
before another CI window. Route actual mistakes into the narrowest existing
skill-feedback issue and retain supersession rather than rewriting history.

Use repository manifest and evaluation machinery. Structural validation,
installation, direct invocation, automatic discovery and demonstrated decision
improvement are separate claims. No authorization, CI-policy or scope expansion
is granted by this skill.
