# Deep research evidence standard

Choose a method matching the question: source archaeology, architecture case study, controlled experiment, benchmark, differential test, replication, systematic review, issue-history analysis, or design research. Separate validity limits when mixing methods.

ACM SIGSOFT's empirical standards define method-specific expectations and criteria including conclusion validity, construct validity, internal validity, reliability, objectivity, and reproducibility: https://www2.sigsoft.org/EmpiricalStandards/

## Source map

Record source ID, kind, commit or DOI or version, authority, exact claim, file or symbol or table extraction, license, independence, and limitations.

## Finding record

Record stable ID; bounded claim; fact, inference, hypothesis, or result class; evidence level; supporting and conflicting sources; confidence; Alpine applicability; correctness, performance, memory, and delivery impact; disposition; linked decision or requirement; and review trigger.

## Threats to validity

Evaluate construct and workload mismatch, implementation confounds, adaptation cost, observer effect, selection and survivorship bias, source dependence, version drift, hardware and thermal drift, insufficient samples, multiple comparisons, benchmark contamination, and unpublished negative results.

## Performance claims

Separate semantic equivalence, adaptation, CPU work, upload, encode or submit, GPU completion, presentation, input-to-photon, allocations, retained memory, physical footprint, and post-close drain. Preserve raw samples and invalidations. Report distributions and confidence intervals, not only averages.

## Review questions

What decision is this for? Which primary evidence and revision? What contradicts it? Can the key result be reproduced? What remains inference? Which project boundary changed? What evidence would reverse the decision?
