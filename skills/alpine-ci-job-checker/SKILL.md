# Alpine CI job checker

Use as the primary skill for Alpine CI design, unexpectedly slow or red jobs,
affected selection, mutation scheduling, duplicate admission, and runtime budgets.
This skill supplies decision discipline, not new authorization or guaranteed
expertise. Repository policy and host restrictions remain binding.

## Start from the execution identity

1. Recover the approved issue, CI intervention plan, current source/base, dirty
   work, live run, and applicable claim/evidence contracts. Preserve held work.
2. Name the failing or costly endpoint and its actual command, package/features,
   target, environment, selector, runner, and cache state. Distinguish a current
   source failure from stale, canceled, queued, or superseded work.
3. State one bounded correction and its falsifier before editing. Keep at most
   two active implementation candidates, including unpublished candidates.

## Preserve completeness before narrowing

- Use Cargo metadata and reverse dependency closure plus explicit edges for
  fixtures, shaders, scripts, manifests, generated inputs, workflow/policy changes,
  toolchains, and feature/cfg combinations. Cargo dependencies alone are incomplete.
- Require an explicit available base and head; cover the whole PR diff and both
  ownership endpoints of renames. Unknown inputs select conservative obligations.
  One mapped path must not hide another unmapped path.
- Distinguish a selector plan from discovery, execution, and accepted evidence.
  Required zero-selection, missing inventory, unexplained omissions, or incomplete
  terminal outcomes cannot pass. Preserve scope-specific legitimate empty work
  only through its accepted contract and discriminating controls.
- For sharding, prove inventory union, disjointness, and terminal outcomes before
  changing counts. Unviable mutants are not killed mutants. Compare baseline and
  mutant package/features, cfg, target, environment, filters, and working-copy
  semantics; an ordinary checkout smoke is not a mutation-copy baseline receipt.

## Order useful feedback

Run fresh metadata checks, syntax/formatting, affected compilation and discovery,
the reproduced regression, corresponding unmutated baselines, and then selected
expensive assurance. For shell syntax, invoke `sh -n` separately for each file:
additional script arguments do not make one invocation validate every file.
Prove early failures leave downstream expensive commands unstarted.

Keep per-shard baseline execution until its replacement has accepted identity,
correspondence, timeout-calibration, and reuse evidence. Never use baseline
skipping to turn an unmutated failure into apparently killed mutants. Native
timeouts remain failures even if an early guard succeeds on another runner.

Prefer the existing Cargo and Alpine assurance interfaces. Do not add Nx, Bazel,
a workflow generator, or a second orchestration platform for this intervention.
Pilot a test-runner change only after inventory, isolation, cleanup, contention,
and failure-reporting equivalence are demonstrated.

## Reduce measured cost

- Separate queue/admission delay, setup, baseline, rebuild, test, cleanup, artifact
  handling, first actionable failure, full feedback, and summed runner cost.
- Compare repeated matched workloads, toolchains, runners, and selected inventories
  in cold and warm cache conditions. A warm local command is not a hosted bound.
- Cache compatible tools/build inputs with explicit identities and trust boundaries.
  Never treat cached outputs or a matching cache key alone as trusted acceptance.
- Separate concurrency from completed-work deduplication. Evidence reuse needs
  exact eligible source/base, policy/workflow, toolchain/target, selectors, and
  assurance-affecting metadata plus fresh metadata validation.
- Treat roughly 15 minutes as a target to calibrate, not a universal promise or
  permission to omit work. Read actual Zed workflows and matched measurements;
  do not assume Zed imposes or achieves a universal 15-minute maximum.

## Close the loop honestly

Before publishing, run the applicable regression, policy, documentation, and
repository gates. Keep exact-head and integrated-main acceptance distinct.
Never enable unsafe merge shortcuts or convert skipped/canceled jobs into success.
Do not move required assurance to scheduled work solely to shorten a PR headline.

Report the changed outcome, source and tested base, evidence ceiling, active and
parked work, remaining blocker, measured cost, and next falsifiable action. Route
live dependencies/status to `github-project-operator`, canonical/Wiki publication
to `github-documentation-architect`, and experimental validity to
`github-deep-researcher` only when their boundary is reached. Native diagnosis may
need `apple-metal-performance-engineer`; workflow expertise does not diagnose GPU
causality from a timeout alone.

Retain failed decisions for independent baseline/candidate evaluation. Installing
this skill, matching required phrases, and critic reviews are not effectiveness
trials. Preserve accepted history rather than silently rewriting unfavorable
results. See [CI evidence and source contract](references/ci-evidence-contract.md).
